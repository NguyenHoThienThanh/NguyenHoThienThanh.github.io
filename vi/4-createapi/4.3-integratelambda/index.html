Tích Hợp API Gateway Với AWS Lambda Function

Cấu hình Quyền Lambda cho API Gateway

Để API Gateway có thể gọi hàm Lambda, bạn cần cấp quyền thích hợp. Điều này được thực hiện bằng cách thêm các vai trò IAM cần thiết vào vai trò thực thi Lambda. Để cấu hình quyền Lambda:

  1. Đi tới Bảng điều khiển AWS Lambda: Truy cập Bảng điều khiển AWS Lambda và chọn hàm Lambda bạn muốn tích hợp với API Gateway.
  2. Tìm vai trò thực thi: Trong tab Cấu hình, cuộn xuống phần Quyền và nhấp vào liên kết dưới Vai trò thực thi để xem vai trò IAM liên kết với hàm Lambda của bạn.
  3. Thêm quyền gọi Lambda: Trong Bảng điều khiển IAM, chọn nút Gắn chính sách để cho phép API Gateway gọi hàm Lambda của bạn. Tìm kiếm AWSLambdaRole hoặc tạo một chính sách tùy chỉnh cấp quyền lambda:InvokeFunction cho hàm Lambda. Gắn chính sách này vào vai trò thực thi Lambda.

Triển khai API Gateway

Sau khi thiết lập hàm Lambda và cấu hình nó làm tích hợp cho phương thức API của bạn, bạn cần triển khai API:

  1. Đi tới Bảng điều khiển API Gateway: Truy cập API của bạn trong Bảng điều khiển API Gateway.
  2. Triển khai API: Trong menu Actions, chọn tùy chọn Triển khai API.
  3. Chọn Giai đoạn triển khai: Chọn một giai đoạn hiện có (ví dụ: dev, prod) hoặc tạo một giai đoạn mới để triển khai API.
  4. Nhấn Triển khai: Sau khi chọn giai đoạn, nhấn Triển khai để làm cho API của bạn hoạt động.
  5. Lấy URL gọi: Sau khi triển khai, bạn sẽ thấy URL gọi dưới chi tiết giai đoạn. URL này sẽ được sử dụng để gửi yêu cầu đến API và kích hoạt hàm Lambda của bạn.

Kiểm tra Tích hợp

Sau khi triển khai API, bạn có thể kiểm tra tích hợp:

  1. Truy cập điểm cuối của API: Đi tới phần Giai đoạn trong Bảng điều khiển API Gateway. Nhấp vào giai đoạn đã triển khai (ví dụ: prod) để xem URL gọi.
  2. Gửi yêu cầu: Bạn có thể kiểm tra việc triển khai bằng trình duyệt, cURL hoặc Postman. Sử dụng URL sau để gửi yêu cầu đến API: 
    GET https://jv8o1qeycb.execute-api.us-east-1.amazonaws.com/dev/items

    Chỉ cần sao chép và dán URL này vào trình duyệt của bạn hoặc sử dụng công cụ như Postman để gửi yêu cầu.

  3. Kiểm tra phản hồi: Nếu mọi thứ đã được cấu hình chính xác, bạn sẽ nhận được phản hồi trả về từ hàm Lambda. Ví dụ, một phản hồi thành công có thể như sau: 
                        HTTP/1.1 200 OK
                    Content-Type: application/json
                    {"message": "Success", "data": [...]}

Sử dụng cURL để Kiểm tra

Để kiểm tra bằng cURL, bạn có thể sử dụng lệnh sau:

curl https://jv8o1qeycb.execute-api.us-east-1.amazonaws.com/dev/items

Lệnh này sẽ gửi yêu cầu GET đến API và xuất phản hồi trong terminal hoặc dấu nhắc lệnh của bạn.

Sử dụng Postman để Kiểm tra

Nếu bạn sử dụng Postman, làm theo các bước sau:

  1. Tạo một yêu cầu DELETE với ID mục: 675d404c4bb43a5febc756a9
  2. Paste URL điểm cuối API vào trường URL yêu cầu: 
    https://jv8o1qeycb.execute-api.us-east-1.amazonaws.com/dev/items/675d404c4bb43a5febc756a9
  3. Nhấn Gửi để thực hiện yêu cầu.
  4. Kiểm tra phản hồi trong cửa sổ Postman. Một phản hồi thành công sẽ trả về trạng thái 200 OK với thông điệp trả về từ Lambda.

Gỡ lỗi và Nhật ký

Nếu có vấn đề xảy ra, bạn có thể sử dụng AWS CloudWatch Logs để gỡ lỗi cả API Gateway và hàm Lambda:

  1. Kích hoạt Nhật ký API Gateway: Để kích hoạt nhật ký cho API Gateway, vào phần Cài đặt Giai đoạn trong Bảng điều khiển API Gateway và chọn hộp kiểm Kích hoạt CloudWatch Logs. Điều này sẽ ghi lại tất cả các yêu cầu và phản hồi, giúp bạn theo dõi hành vi của API.
  2. Xem Nhật ký Lambda: Trong bảng điều khiển Lambda, bạn có thể truy cập các nhật ký do hàm Lambda tạo trong CloudWatch, điều này giúp bạn gỡ lỗi các vấn đề của hàm Lambda.

Bảo mật API Gateway và Tích hợp Lambda

Để đảm bảo truy cập an toàn vào hàm Lambda của bạn qua API Gateway, bạn có thể triển khai các cơ chế bảo mật sau:

  1. Bảo mật dựa trên vai trò IAM: Đảm bảo rằng chỉ các người dùng hoặc dịch vụ được ủy quyền có thể gọi hàm Lambda của bạn bằng cách gán các vai trò IAM thích hợp cho những người dùng hoặc dịch vụ sẽ truy cập API.
  2. API Key: Cấu hình khóa API trong API Gateway để giới hạn quyền truy cập cho các khách hàng được ủy quyền. Bạn có thể tạo khóa API trong bảng điều khiển API Gateway và gắn chúng vào các phương thức để kiểm soát quyền truy cập.
  3. Lambda Authorizer: Sử dụng một Lambda authorizer (trước đây gọi là custom authorizer) để thêm logic xác thực tùy chỉnh kiểm tra các yêu cầu đến trước khi chúng được chuyển đến hàm Lambda của bạn.
  4. CORS (Chia sẻ Tài nguyên Gốc Chéo): Nếu API của bạn được truy cập từ các trình duyệt web trên các miền khác nhau, hãy cấu hình CORS để cho phép các yêu cầu chéo an toàn. Điều này có thể thực hiện trong cài đặt phương thức API Gateway.

Suy nghĩ Cuối cùng

Bằng cách làm theo các bước này, bạn đã thành công trong việc tích hợp Lambda với API Gateway, tạo ra một API không máy chủ. Với thiết lập này, API Gateway quản lý định tuyến, quản lý lưu lượng, bảo mật và ghi nhật ký, trong khi Lambda xử lý logic cho các thao tác API của bạn.

  • Lambda: Xử lý các yêu cầu và trả về phản hồi.
  • API Gateway: Quản lý lưu lượng, bảo mật, định tuyến và kích hoạt các hàm Lambda khi cần.

Kiến trúc không máy chủ này tự động mở rộng, giúp bạn không phải quản lý máy chủ và đảm bảo API của bạn có thể xử lý lưu lượng tăng lên một cách hiệu quả.
